# GoEvent Design System

Follow these conventions whenever you build or modify UI in this repo. When in doubt, copy the closest existing component and match it exactly ([EventCard.vue](src/components/EventCard.vue), [EventCreateDrawer.vue](src/components/EventCreateDrawer.vue), [DeleteConfirmModal.vue](src/components/DeleteConfirmModal.vue) are the canonical references). The app is **light-mode only** — do not introduce dark-mode variants.

## 1. Brand & Color

> Brand identity — logo assets, exact logo gradient colors, logo usage rules, and governance — is defined in [DESIGN.md](DESIGN.md) (§1). This skill covers the working UI conventions.

- **Brand gradient** (primary CTA, drawer headers, FABs, active nav/filter states, hero accents):
  `bg-gradient-to-r from-[#2ecc71] to-[#1e90ff]` with hover `hover:from-[#27ae60] hover:to-[#1873cc]` (or `hover:opacity-90` on small buttons).
  Use the raw hex arbitrary values — that is the established convention (43+ usages), not the `brand-*` Tailwind aliases. A few older spots use `from-emerald-500 to-blue-500`; prefer the hex form for new code.
- **Tinted brand surfaces**: soften the gradient with alpha for backgrounds — `from-[#2ecc71]/20 to-[#1e90ff]/20` (empty-state icon discs), `/10` for placeholders.
- **Neutrals**: `slate` is the ONLY neutral scale — never use `gray-*`, `zinc-*`, `neutral-*`, or `stone-*` utilities (the codebase was fully migrated from `gray` to `slate`; do not reintroduce it). Scale: `text-slate-900` headings, `text-slate-700` labels, `text-slate-600` body, `text-slate-500` muted, `text-slate-400` placeholder/disabled, `border-slate-300` inputs, `border-slate-200` cards/dividers, `bg-slate-50/100` subtle fills, `bg-slate-900` dark tooltips.
- **Focus / interactive accent** in forms: `sky` (`focus:ring-sky-200 focus:border-sky-400`, toggles `bg-sky-500`, icons `text-sky-500`).
- **Status colors**: green-500/600 = live/registered/success, `#1e90ff` = upcoming/info, slate-600 = past/neutral, red-500/600 = destructive/error, yellow-500 = warning, purple = private-event accents.
- **Dynamic entity colors** (categories, guest groups): inline style with hex + alpha suffix, e.g. `backgroundColor: ${event.category_color || '#3B82F6'}E6`; indicator dots are `w-3 h-3 rounded-full flex-shrink-0`.
- Fonts: `Figtree` (Latin) + `Kantumruy Pro` (Khmer) via the default `font-sans`. Showcase templates load their own fonts dynamically — never hardcode fonts there; use the template's `primaryFont`/`secondaryFont` props.

## 2. Typography scale

Mobile-first with `sm:`/`lg:` bumps — never a fixed large size on mobile:

| Role | Classes |
|---|---|
| Page title | `text-2xl sm:text-3xl lg:text-4xl font-bold text-slate-900` |
| Section/empty-state title | `text-xl lg:text-2xl font-bold text-slate-900` |
| Card title | `text-lg sm:text-xl font-semibold text-slate-900 line-clamp-2` |
| Panel/drawer header | `text-base font-semibold` |
| Body / description | `text-sm sm:text-base text-slate-600 leading-relaxed` |
| Meta / captions | `text-xs sm:text-sm text-slate-500` |
| Form section heading | `text-xs font-semibold text-slate-500 uppercase tracking-wider` |
| Micro labels (nav) | `text-[10.5px] font-medium` |

Weights: `font-bold` page/section titles, `font-semibold` card titles + primary buttons, `font-medium` labels/badges/secondary buttons. Long user text always gets `truncate` or `line-clamp-2`.

## 3. Radius, shadow & blur scales

- **Radius** (pick by component size, don't invent): `rounded-lg` (8px) inputs, small buttons, badges, icon buttons · `rounded-xl` (12px) toasts, dropdown menus, list rows, large buttons · `rounded-2xl` (16px) cards, drawer panels · `rounded-3xl` (24px) modals, glass section panels · `rounded-full` pills, avatars, FABs, toggles, icon discs.
- **Shadow**: `shadow-sm` chips/subtle cards · `shadow-md` badges, active pills, small CTAs · `shadow-lg` toasts, FABs (with colored tint like `shadow-emerald-500/25`) · `shadow-xl` glass panels, dropdown menus · `shadow-2xl` drawers, modals.
- **Glassmorphism** (signature surface): `bg-white/80 backdrop-blur-sm border border-white/20` for panels; `bg-white/90 backdrop-blur-sm` for badges/buttons over images; `rgba(255,255,255,0.6)` + `blur(12px)` for toggle groups. Backdrops: `bg-black/40` (drawers) or `bg-black/50` (modals) + `backdrop-blur-sm`.

## 4. Layout & Pages

- Page shell: wrap in `<MainLayout>`; content section `py-4 sm:py-6 lg:py-8` inside `max-w-4xl lg:max-w-5xl 2xl:max-w-6xl mx-auto px-4 sm:px-6 lg:px-8`. Top-level list pages (Events/Discover/Services) add the subtle brand tint on the page wrapper: `bg-gradient-to-r from-[#2ecc71]/[0.02] via-white to-[#1e90ff]/[0.02]`.
- Page title row: `flex items-center justify-between gap-2` header, one line, no wrap; `mb-6 sm:mb-8 lg:mb-10`. Title gets `flex-1 min-w-0 truncate` so it yields space instead of pushing controls off-screen or wrapping the row. When there's more than one right-side control (e.g. a time toggle + category filter), group them in `flex items-center gap-1.5 sm:gap-2 flex-shrink-0` so the group holds its size and never wraps.
- Vertical rhythm: sibling sections `space-y-5` or `space-y-6 sm:space-y-8`; within a group `space-y-3`; grids `gap-3` (forms) to `gap-6` (card grids).
- **Every page needs four states**: loading skeleton, populated content, empty state, and (where auth-gated) unauthenticated state. Reuse `EventsLoadingSkeleton` / `EventsEmptyState` patterns.
- **Bottom-anchored chrome positions off the shared inset vars, never a hardcoded offset.** `MobileTabBar` is a *floating pill*, so the band it occupies is its height plus the safe-area gap it floats above the edge by — 66px on Android, ~88px on a notched iPhone, which is why the old fixed `bottom-20` (80px) put FABs *under* the pill on the latter. [MainLayout.vue](src/components/MainLayout.vue) publishes three vars, all 0/edge-relative on desktop and on `nav-inset-none` pages (those rendered with `hide-mobile-tab-bar`):
  - `--nav-inset` — the band the pill occupies. Use for page bottom pad (`pb-[var(--nav-inset)]`, already applied by MainLayout around the slot — don't add a second copy inside it), full-width bars that stack on the pill (`bottom-[var(--nav-inset)]`), and sticky-footer math (`min-h-[calc(100vh-var(--nav-inset))]`).
  - `--fab-bottom` — the primary floating action's bottom edge.
  - `--fab-stack-2` — the slot above it, for a secondary FAB.
- FAB: `fixed bottom-[var(--fab-bottom)] right-4 lg:right-6 w-12 h-12 lg:w-14 lg:h-14`, brand gradient, `rounded-full shadow-lg shadow-emerald-500/25 hover:shadow-emerald-600/30 transition-all duration-300 hover:scale-110 active:scale-95 z-[60] group`; icon animates (`group-hover:rotate-90` for Plus). **A size down on mobile** — it is a satellite of the floating pill, and at desktop size the two read as competing objects rather than as bar-plus-action. A secondary FAB above it (support/contact) goes one size smaller again: descending sizes up the column are what stop a stack reading as peers. The tooltip pill (`bg-slate-900 text-white px-3 py-2 rounded-lg text-sm`) fades in on the left and is **`hidden lg:block`** — on touch there is no hover to reveal it, only a press that leaves it stuck on screen. A FAB's own popover/nudge belongs inside the same fixed wrapper (`absolute bottom-full mb-3 right-0`), never separately fixed with its offset restated.

## 5. Navigation

- **Breakpoint rule: `lg` (1024px) is the desktop/mobile navigation switch.** Desktop chrome is `hidden lg:flex`; mobile chrome is `lg:hidden`.
- Top bar height is `4rem` — fixed sub-navigation sits at `top-16`.
- **Mobile bottom tab bar** ([MobileTabBar.vue](src/components/MobileTabBar.vue)): a **floating pill**, not a bar on the edge — the page runs to the bottom of the screen behind it. Click-through wrapper `lg:hidden fixed inset-x-0 bottom-0 z-[70] pointer-events-none`, inner `relative pb-[max(0.75rem,env(safe-area-inset-bottom))]`, pill `pointer-events-auto mx-auto w-fit max-w-[calc(100vw-1.5rem)] rounded-full border border-white/50 p-1.5 flex items-center gap-0.5` over the brand-tinted `.glass-pill` (all-sides shadow + `inset 0 1px 0 rgba(255,255,255,0.7)` lip). Tabs are `h-10 rounded-full`: the active one carries its label (`pl-3 pr-3.5`), the rest are icon-only (`w-10`/`px-2.5`, `text-slate-500`) — five labels would force the pill back to full width. **Reveal the label through a grid column** (`grid-cols-[0fr]` → `grid-cols-[1fr]`, §15), never `max-width`, and delay its fade-in (~200ms) / speed its fade-out (~100ms) so the text is never outside the gradient. **The gradient is one travelling element**, absolutely positioned in an unpadded row and measured off `[aria-current="page"]` — not a background on each tab, since `background-image` can't be interpolated and would pop. Its target is re-measured every frame while it moves, because the tabs are still relaying out underneath it. **Nav chrome is rebuilt on every navigation** (each view renders its own `MainLayout`), so a transition across routes needs the outgoing tab remembered in module scope — outside `<script setup>`, which re-runs per instance — and applied for one frame on mount before switching to the real route. Non-navigating items in the pill (notifications, profile) stay icon-only and show state with a `bg-slate-900/[0.06]` fill. Expanding menus open with `absolute bottom-full left-3 right-3 mb-3` as a `rounded-3xl` glass card; menu rows are `flex items-center space-x-2 px-3 py-2 text-slate-700 hover:bg-slate-50 rounded-xl transition-all duration-200`.
- **Manage-page desktop sidebar** ([EventNavigationTabs.vue](src/components/EventNavigationTabs.vue)): fixed icon rail `w-[88px]` glass with `border-r border-slate-200/30 z-40`, items are icon-over-label (`w-5 h-5` icon, `text-[10.5px]` label); active state = gradient edge bar (`absolute left-0 w-0.5 h-10 bg-gradient-to-b from-[#2ecc71] to-[#1e90ff] rounded-r-sm`) + `text-[#2ecc71]` icon; inactive `text-slate-400 group-hover:text-slate-600`.
- **Manage-page mobile tab bar** ([EventManageMobileTabBar.vue](src/components/EventManageMobileTabBar.vue)): `lg:hidden fixed top-16 z-40`, horizontally scrollable (`overflow-x-auto scrollbar-hide`) with gradient edge-fade hints on both sides; active tab = `text-[#2ecc71] font-semibold` + gradient underline (`w-8 h-0.5 bg-gradient-to-r from-[#2ecc71] to-[#1e90ff] rounded-t-sm`); inactive `text-slate-500`, `active:scale-95` press feedback; `min-h-[40px]` touch targets.
- **Segmented control / pill toggle** ([TimeFilterToggle.vue](src/components/events/TimeFilterToggle.vue)): glass container `rounded-full p-1` (white/60 + blur 12px + white/50 border); options `px-3 sm:px-4 py-1.5 sm:py-2 text-sm font-medium rounded-full transition-all duration-300`; selected = brand gradient + white text + `shadow-md shadow-[#2ecc71]/20`; unselected = `text-slate-600 hover:text-slate-800`.

## 6. Buttons

All buttons: `text-sm font-medium` (primary uses `font-semibold`), `rounded-lg` (or `rounded-xl` when large/prominent), `disabled:opacity-50 disabled:cursor-not-allowed`, `transition-colors duration-200` (or `transition-all` if shadow/transform changes). Icon+label buttons use `flex items-center gap-2` with `w-4 h-4` icons.

| Variant | Recipe | Use |
|---|---|---|
| Primary | `px-4 py-2 bg-gradient-to-r from-[#2ecc71] to-[#1e90ff] text-white font-semibold rounded-lg hover:opacity-90 shadow-md` | Submit/save/create |
| Secondary | `px-4 py-2 text-slate-600 bg-slate-100 hover:bg-slate-200 rounded-lg` | Cancel, neutral actions |
| Ghost | `px-4 py-2 text-slate-600 hover:bg-slate-100 rounded-lg` | Tertiary/dismiss |
| Dark solid | `px-5 py-2.5 lg:px-6 lg:py-3 bg-slate-900 hover:bg-slate-800 text-white rounded-xl` | Empty-state CTAs |
| Destructive | `bg-red-600 hover:bg-red-700 text-white rounded-lg sm:rounded-xl` | Delete/confirm-danger |
| Icon-only | `p-1.5` or `p-2`, `hover:bg-slate-100` (or `hover:bg-white/20` on gradient headers), `rounded-lg`, with `title`/`aria-label` | Toolbars, close buttons |

**Loading state**: swap the leading icon for `Loader` with `animate-spin` (or a `border-2 border-white border-t-transparent rounded-full animate-spin` div), swap the label ("Create" → "Creating…"), disable the button, and guard the handler on the loading flag.

## 7. Cards

**List/grid cards (EventCard pattern):**
- Container: `group relative bg-white rounded-2xl border border-slate-200/60 hover:border-slate-300/80 transition-all duration-300 hover:shadow-lg hover:shadow-slate-200/40 cursor-pointer overflow-hidden flex flex-col`, plus `role="article"` and an `aria-label`.
- Banner: `aspect-[1.9/1]` (1200×630), image `object-cover transition-transform duration-500 group-hover:scale-105`. Two-stage image fallback (primary → category fallback → gradient placeholder with icon).
- Badges over images: pill `inline-flex items-center text-xs sm:text-sm font-medium px-2.5 sm:px-3 py-1 sm:py-1.5 rounded-lg shadow-md`; solid color for status (with a `w-1.5 h-1.5 bg-white rounded-full` dot, `animate-pulse` for Live), `bg-white/90 backdrop-blur-sm` + colored text/border for type badges (Private/Virtual).
- Hover-revealed actions (delete etc.): absolutely positioned, `opacity-0 group-hover:opacity-100`, button is `bg-white/90 backdrop-blur-sm rounded-lg border` with red hover states; call `event.stopPropagation()` in the handler.
- Body: `p-4 sm:p-5 md:p-6 flex flex-col flex-1`; title per §2; meta rows use lucide icons `w-4 h-4 mr-2 text-slate-500 flex-shrink-0` + `truncate` text; footer sits at `mt-auto` behind `pt-3 border-t border-slate-100`. Avatars: `w-6 sm:w-7` rounded-full circles, stacked with `-space-x-2` + `border-2 border-white` and a `+N` overflow circle.
- Images go through ImageKit: rewrite `api.goevent.online/media/` → `ik.imagekit.io/goevent/media/` and inject `tr:w-…,h-…` sized ~2–3× the display size.

**Manage-page section cards (glassmorphism):**
`bg-white/80 backdrop-blur-sm border border-white/20 rounded-3xl shadow-xl` with `p-6 sm:p-8` (or `p-8 sm:p-12 text-center` for empty states). Use this for the big content panels inside EventManageView tabs.

**Showcase-tab section panels + row lists (the standard for manage sections):**
Pattern from [EventTextTab.vue](src/components/EventTextTab.vue), also used by the embedded Agenda/Hosts sections ([EventAgendaTab.vue](src/components/EventAgendaTab.vue) / [EventHostsTab.vue](src/components/EventHostsTab.vue) in `embedded` mode). The Showcase tab stacks these panels; content entities render as tappable rows, and all editing happens in a drawer (§10).

- Panel: glass card per above but `p-4 sm:p-6`; header = `h5 font-semibold text-slate-900` title + `text-sm text-slate-600` subtitle, with an optional **dashed add pill** right-aligned: `inline-flex items-center gap-1 px-3 py-1.5 text-sm font-medium text-slate-600 border border-dashed border-slate-300 rounded-full hover:border-emerald-300 hover:text-emerald-700 hover:bg-emerald-50 active:bg-emerald-50 transition-all` with a `w-3.5 h-3.5` Plus/UserPlus icon. Desktop-only drag hint (`hidden sm:flex text-xs text-slate-400` + arrows svg) goes under the subtitle when rows are reorderable.
- Group micro-heading above each row card: `text-xs font-semibold text-slate-500 uppercase tracking-wider` with a muted count (`<span class="text-slate-400">· {{ n }}</span>`); per-group icon actions (edit/delete day, etc.) right-aligned as `p-1.5 text-slate-400 hover:text-[#1e90ff] hover:bg-sky-50` / `hover:text-red-600 hover:bg-red-50` `rounded-lg`.
- Row card: `bg-white rounded-2xl border border-slate-200 divide-y divide-slate-100 overflow-hidden`; each row is a `<button>` — `w-full flex items-center gap-3 p-3 sm:p-4 min-h-[56px] text-left hover:bg-slate-50 active:bg-slate-100 transition-colors duration-200 focus:outline-none focus-visible:ring-2 focus-visible:ring-sky-200 focus-visible:ring-inset`.
- Row anatomy: **leading element** (entity-specific: `w-9 h-9 rounded-lg` icon disc for texts, plain `whitespace-nowrap` time stack for agenda, `w-10 h-10 rounded-full` avatar for hosts) → **body** (`flex-1 min-w-0`): title line = `text-sm font-medium truncate` + right-aligned **language completion chips**, then a `text-xs sm:text-sm text-slate-500 line-clamp-1` preview line (agenda adds a color-tinted type badge here: `px-1.5 py-0.5 rounded text-[10px] font-medium` with inline `backgroundColor: withAlpha(accent,'14'); color: accent`) → trailing `ChevronRight w-4 h-4 text-slate-400`.
- Language completion chips: `text-[10px] font-semibold px-1.5 py-0.5 rounded border uppercase`; filled = `bg-emerald-50 text-emerald-700 border-emerald-200`, missing = `bg-white text-slate-400 border-dashed border-slate-200`, inactive/hidden = `bg-amber-50 text-amber-600 border-amber-200`. Show chips only when >1 language is in play; order via `sortEventTextLanguages`.
- Per-item entity color (agenda): slim left accent bar via `boxShadow: inset 3px 0 0 0 ${withAlpha(accent,'66')}` on the row (inset shadow, not border-left, so it doesn't fight the card radius).
- Row drag-and-drop reorder (desktop): rows are `:draggable="canEdit"`; source dims (`opacity-50`), the hovered target highlights `bg-sky-50`; drop on a target row reorders relative to it (optimistic update + rollback). HTML5 DnD doesn't fire on touch — mobile edits via the drawer.
- States: loading skeleton mirrors the rows (micro-heading bar + 2–3 skeleton rows in the same card chrome); empty state is a clickable dashed box `border-2 border-dashed rounded-2xl p-8 text-center` (`border-slate-200 bg-slate-50/50 hover:bg-slate-100/50 hover:border-emerald-400 cursor-pointer group` when editable) with a `w-8 h-8` icon and title/description.

## 8. Forms

- Label: `block text-sm font-medium text-slate-700 mb-2`; required fields append ` *`.
- Text/date/select input: `w-full px-3.5 py-2.5 text-sm border border-slate-300 rounded-lg focus:outline-none focus:ring-2 focus:ring-sky-200 focus:border-sky-400 bg-white`. Selects add `appearance-none pr-10` with an absolutely-positioned `ChevronDown` (`w-4 h-4 text-slate-400 right-3 top-1/2 -translate-y-1/2 pointer-events-none`).
- Section heading inside forms/drawers: uppercase micro-heading per §2; sections spaced `space-y-5`, fields within a section `space-y-3`; two-column rows via `grid grid-cols-1 sm:grid-cols-2 gap-3` (single column on mobile, always).
- Toggle row pattern (settings-style boolean): **use the grouped inset list below** — `.list-group` + `.list-row` from [groupedList.css](src/components/common/groupedList.css), or `TemplateFormSwitch` inside the templates editor. The standalone `bg-slate-50 rounded-lg` row with an icon chip that this line used to specify no longer exists anywhere in the repo: the event drawers dropped it, and the partner template editor's nine switches followed. Do not reintroduce it — a run of these rows stacked on each other is what the grouped list is for, and knob travel in `px` breaks under the 75% root-font downscale the app applies on short laptop viewports.
- Conditionally revealed fields wrap in `<Transition name="slide-fade">` (enter `0.3s ease-out`, leave `0.2s ease-in`, from `opacity-0 translateY(-10px)`).
- **Text inputs on phones are 16px, not 14px** — `text-base sm:text-sm`, or `.list-input`, which does it for you. Mobile Safari zooms the whole page when a focused input measures under 16px, and inside a drawer or a locked showcase there is no way back out. Desktop is unaffected; the recipe above is the desktop size.

**Grouped inset list** ([groupedList.css](src/components/common/groupedList.css), reference: [EventCreateDrawer.vue](src/components/EventCreateDrawer.vue)) — the denser alternative to a run of separate `bg-slate-50` toggle rows, for a drawer's settings-style controls. One `.list-group` (white, `border-slate-200`, `rounded-xl`, `overflow-hidden`, hairline `border-slate-100` between children) holding any mix of `.list-row`s:

- **Switch row** — `.list-row__text` (label + optional `.list-row__hint`) on the left, `.switch-track`/`.switch-knob` on the right. No icon chip: a `p-2 bg-white rounded-lg shadow-sm` disc inside a row inside a bordered group is card-in-card, and three identical sky icons in one group read as texture (goevent-taste §3, §7). Keep an icon only where it *carries state*.
- **Field row** — label on the left, a borderless right-aligned `.list-input` on the right. The group's border is already drawn around it, so a second border inside makes the row read as a card containing a field. Focus ring goes on the row (`:focus-within`), never on the bare input.
- **Disclosure row** — [DateTimeDisclosureRow.vue](src/components/common/DateTimeDisclosureRow.vue): label, trailing value, chevron; expands its editor **in place** via the `collapse`/`drawer-reveal` transition. Inside a drawer this replaces opening a picker sheet — a `z-[1001]` sheet over a `z-[999]` drawer is a modal over a modal, with a second scrim and a second Escape target, for a field the user is already looking at. Keep sibling rows mutually exclusive, and scroll the row into view on `@after-enter`, never on click (the reveal animates for 350ms, so an earlier measurement is of the collapsed row).
- **Press feedback is a row highlight, instant on the way in** (`:active { transition: none }`), eased on the way out. Never `active:scale-*` on a full-width row — a 0.99 scale moves a 560px row by under 3px at its widest point and by nothing at its centre.

**Segmented control** ([SegmentedField.vue](src/components/common/SegmentedField.vue)) — for a choice between two or three *named* things. A switch whose label flips with its state (`Public Event` ↔ `Private Event`) has no stable off-meaning and hides the alternative; if both states have names, show both. `role="radiogroup"` + `role="radio"` with roving tabindex; white cap on a `bg-slate-100` track, sliding on `transform 0.28s cubic-bezier(0.32,0.72,0,1)`. **Not** the brand gradient — a drawer already spends its gradient on the header and the primary action (goevent-taste §2).

**Cards or segments — pick by what the choice *is*.** Both render one-of-N, and the wrong one is the commonest control mistake in this repo's editors:

- **A magnitude → segmented.** `light / normal / heavy`, `slow / normal / fast`, `subtle / normal / bright`. The values are *ordered*, and three separate boxes throw that ordering away; one track puts the steps in their own order, so the control's shape maps to what it changes. A card whose entire content is one word is also a card with nothing to put in it. `TemplateFormChoice` takes `variant="segmented"` for exactly this and delegates to `SegmentedField` — never hand-roll a second track.
- **A look → radio cards.** Which host layout, which agenda composition, artwork cover vs filmed cover. These are unordered, and each option has a description and often an icon to carry — content a segment has nowhere to put. Full-width (`:columns="1"`) when the descriptions are real sentences.
- **A long list → `TemplateFormSelect`.** Fonts, particle types. Past roughly six options, showing them all costs more than it returns.

**Time entry**: [TimeWheel.vue](src/components/common/TimeWheel.vue) — two `scroll-snap-type: y mandatory` columns under one centred band, built on native overflow scrolling so momentum, rubber-banding and mid-fling interruption come from the platform. `overscroll-behavior: contain` is load-bearing: without it the last flick scrolls the drawer behind it. Never nest a popover listbox inside a picker panel for this.
- **Validation errors**: field-level API errors arrive as `{ field: ["msg"] }`; show under the input as `text-xs sm:text-sm text-red-600 mt-1` and add `border-red-300 focus:ring-red-200 focus:border-red-400` to the invalid input. Global form errors go in a toast or an inline `bg-red-50 border border-red-200 text-red-700 rounded-lg p-3 text-sm` banner.
- All user-facing strings via i18n `t(...)` from `useAppLanguage` — never hardcode; add keys to **both** `en` and `kh` locale files.

## 9. Dropdowns & menus

Pattern from `GuestGroupsView.vue` (full reference: [DROPDOWN_STYLING_GUIDE.md](src/components/invitation/DROPDOWN_STYLING_GUIDE.md)):

- Trigger: `flex items-center gap-2 px-3 py-2 bg-white border border-slate-200 rounded-lg text-sm font-medium hover:border-emerald-300 hover:bg-emerald-50 transition-all`; label `flex-1 text-left truncate`; trailing `ChevronDown w-4 h-4 text-slate-400 transition-transform` with `rotate-180` bound to open state.
- Menu: `absolute top-full left-0 mt-2 min-w-[250px] bg-white border border-slate-200 rounded-xl shadow-xl z-[100] max-h-[400px] overflow-y-auto`, rendered with `v-if` inside `<Transition name="dropdown">` (`0.2s ease`, from `opacity-0 translateY(-10px)`).
- Items: `w-full flex items-center gap-3 px-4 py-3 text-sm font-medium transition-all duration-200`; default `text-slate-700 hover:bg-slate-50`; selected = brand gradient + white text. Dividers: `border-t border-slate-100`. Counts as trailing `text-xs opacity-75`.
- Close behavior: transparent click-outside overlay `fixed inset-0 z-[90]` (menu itself at `z-[100]`), plus close on item select; support Escape where practical.

## 10. Drawers (create/edit flows)

## 12. Toasts & notifications

**There is exactly one toast stack in the app.** Never render toast markup inside a feature component — that is how toasts used to end up overlapping each other and hiding behind the FABs. Call the composable; [ToastHost.vue](src/components/ToastHost.vue), mounted once in [App.vue](src/App.vue), renders everything.

```ts
const { showSuccess, showError, showWarning, showInfo } = useToast()
showSuccess('Event published')
showError('Upload failed', { description: 'The file is larger than 10 MB.' })
showError('Needs your attention', { duration: 0 }) // sticky until dismissed
```

- **API** ([useToast.ts](src/composables/useToast.ts)): `showToast(type, title, options?)` plus the four type shorthands; `options` is `{ description?, duration?, dismissible? }` (a bare number is accepted as the duration). Also `dismissToast(id)`, `clearToasts()`, `pauseToasts()`/`resumeToasts()`. [useNotifications.ts](src/composables/useNotifications.ts) is a title+message adapter over the same queue — either is fine, `useToast` is preferred for new code.
- **Not every confirmation is a toast — most are not.** Before reaching for `useToast`, ask *where the result already is*. Three answers, in order of preference:
  1. **The result is on screen.** A row appears in the list, a price redraws with a discount applied, a status card behind a closing drawer flips to "pending review". Say nothing — the screen already said it. (Quick-add guest, applying a promo code.)
  2. **The control can answer.** Flip it to a tick and a past-tense word for ~1.5s: `Copy → Copied`, `Use this template → Template applied`, `Activate now → Template activated`. Use [useActionConfirmation.ts](src/composables/useActionConfirmation.ts) — `const { confirmed, confirm } = useActionConfirmation()`, then `confirm(() => closeDrawer())` so the hold and the follow-up are one thing and every control holds for the same beat. A modal that already waits before closing spends that wait *confirming*, not still spinning on a request that returned.
  3. **Neither.** Then toast — and only then.
- **A primary action that confirms itself uses the three-face button**: [actionButton.css](src/components/common/actionButton.css), attached per component with `<style scoped src="…/common/actionButton.css">` (Vue compiles a separate scoped copy, so its keyframes stay resolvable). Markup is `.action-btn` + `grid` on the button and three `.action-face` spans keyed by `:data-on`, so all three states share one grid cell and the button never resizes mid-save. Colour-agnostic — the brand gradient on the drawer footers, `bg-slate-900` on the sign-in submit. It supplies the whole feel: one rise-and-settle as the tick lands, a blur-bridged face swap, a 0.7s spinner, and full `prefers-reduced-motion` fallbacks. See [EventCreateDrawer.vue](src/components/EventCreateDrawer.vue), [EventEditDrawer.vue](src/components/EventEditDrawer.vue) and [SignInCard.vue](src/components/auth/SignInCard.vue) — the last also shows the pattern in a row that cannot stack faces (the provider buttons swap logo → spinner → tick in place). Four rules it encodes, each of which was a bug first:
  - **Never stagger opacity** across the two faces. They are a crossfade, so the eye reads the *sum*; staggered curves punch a hole in the middle — measured at 0.35 — while equal-duration `linear` holds it at 1.0. The asymmetry that sells the swap lives in blur and transform, where a dip costs nothing.
  - **Write the three labels to roughly equal length.** The button is sized to the widest and never resizes, so "Update Event" / "Saving…" / "Event updated" fills it, while "Update Event" / "Saving…" / "Saved" left 47px of dead fill and read as an empty slab. Past tense of the whole action, not a bare participle.
  - **Keep the button its own colour in every state.** A flat success green cross-faded over the gradient was tried, and reads as a saturated slab fighting the gradient header right as the drawer leaves. The tick and the past tense already say "done".
  - **Hold 900ms on a drawer that closes itself, 550ms on a gate like sign-in.** The swap alone costs ~280ms, so anything shorter closes on a tick that never finished arriving; but on a gate every millisecond is a toll, and there the tick stays up for free while the route resolves. Blocked dismissal while busy is part of the drawer contract — backdrop, header close and Escape all no-op until the hold ends. A button *also* disabled for a non-busy reason (an unfilled form) adds `is-unavailable`, restoring a plainly-disabled 0.4 over the working state's held 0.75.
- **Failures always toast** (or use an inline banner where there's room to explain). A control returning to idle cannot say why, and a closing drawer takes its own error text with it. This is why `useActionConfirmation` has no failure state: the asymmetry is deliberate.
- Two feedbacks for one action is the same news twice. When a component confirms in place, the handler that performs the work must be told to stay quiet — see `copyShowcaseLink`'s `silent` flag in [EventGuestManagementTab.vue](src/components/EventGuestManagementTab.vue). Suppression is **not** viewport-conditional: a rule that fires a bar on desktop and not on mobile makes the same code path unreadable, and the redundancy is just as real on a wide screen.
- **Behaviour**, all handled by the host: success/info dismiss after 4s and error/warning after 6s (`duration: 0` = sticky); the countdown pauses on hover, on keyboard focus, and while the tab is backgrounded; re-raising a message that is already on screen refreshes its timer and bumps a `×N` chip instead of stacking a duplicate. The stack caps at **3 on desktop and 1 below `lg`** — two bars over a phone-width list read as a takeover — evicting the oldest.
- **Placement**: bottom-right from `lg` (`lg:right-[var(--toast-right,6rem)] lg:bottom-[var(--fab-bottom,1rem)]`) — the corner people expect a notification in, sharing the FAB's baseline but sitting in the lane *beside* the FAB column, never over it. `--toast-right` is published with the other bottom-chrome slots in [MainLayout.vue](src/components/MainLayout.vue); never hardcode it. Below `lg` the stack hangs from the top instead (`top-[calc(env(safe-area-inset-top,0px)_+_4.5rem)]`, centered): a phone's bottom band is entirely floating tab bar and FABs. `z-[1100]` throughout, so it clears drawers (`z-[999]`) and modals (`z-[1000]`).
- **Toast surface**: `rounded-xl border border-white/70 bg-white/95 backdrop-blur-xl px-3 py-2.5 shadow-lg shadow-slate-900/[0.08] ring-1 ring-slate-900/[0.06]` — a compact glass row, ~44px for a one-line message. Type reads from a `h-6 w-6 rounded-full` icon disc and nothing else: `bg-green-50 text-green-600` (success — the brand's `#2ecc71` lives in `green`, not `emerald`) / `bg-red-50 text-red-600` / `bg-amber-50 text-amber-600` / `bg-sky-50 text-[#1e90ff]`. Title `text-[13px] font-semibold text-slate-900 line-clamp-2`, description `text-xs text-slate-500 line-clamp-2`. **No progress bar** — a saturated band across the full width was the loudest thing on screen for a message that says "copied", and hover-pause never depended on it.
- **Dismissal**: `X` button (`h-6 w-6 rounded-md text-slate-400 hover:bg-slate-100`, hit area extended with `after:absolute after:-inset-2`) with an i18n `aria-label`, or drag the toast *away from its anchored edge* past ~56px — down on desktop, up on mobile, matching the direction it entered from (releases short of that spring back). Each toast carries `role="status"`/`role="alert"` + `aria-live`; motion collapses under `prefers-reduced-motion`.
- **Motion**: enter 260ms `cubic-bezier(0.32, 0.72, 0, 1)` from `translateY(±12px) scale(0.97)` (sign follows the anchor), leave 180ms, reflow 240ms. Never below `scale(0.9)` — nothing appears out of nothing.
- **Inside a drawer**, a message tied to the drawer's own save action may stay inline above the footer (`absolute bottom-16 left-4 right-4 z-10`) so it reads next to the button that produced it — see [EventEditDrawer.vue](src/components/EventEditDrawer.vue). Everything else goes through `useToast`.

## 15. Motion language (general UI)

- Micro-interactions: `transition-colors duration-200`; composite hovers `transition-all duration-300`; image zooms `duration-500`.
- Scale on hover only for FABs/primary CTAs (`hover:scale-110`); cards lift via border + shadow instead. Mobile press feedback: `active:scale-95`.
- Vue `<Transition>` names in use: `fade` (backdrops), `slide-right` (drawers), `slide-fade` (conditional form fields), `modal` (dialogs), `slide-up` (mobile sheet panels, in-drawer inline messages), `dropdown` (menus), `toast` (the toast TransitionGroup in [ToastHost.vue](src/components/ToastHost.vue)), `sheet` (bottom sheets), `collapse` (expand/collapse sections).
- **Expand/collapse sections** (accordion rows, collapsible cards, "more details" reveals): use the `collapse` transition on a grid wrapper — never `max-height` animation (a large cap makes one direction ease unevenly with dead time). Markup: `<Transition name="collapse"><div v-if="open" class="grid grid-rows-[1fr]"><div class="min-h-0 overflow-hidden"><div class="pt-…"> content </div></div></div></Transition>` — content padding/margins go on the innermost layer so they collapse too. CSS: `.collapse-enter-active, .collapse-leave-active { transition: grid-template-rows 0.35s cubic-bezier(0.4, 0, 0.2, 1), opacity 0.3s ease; }` and `.collapse-enter-from, .collapse-leave-to { grid-template-rows: 0fr; opacity: 0; }`, disabled under `prefers-reduced-motion`. Works with `v-if` and `v-show`; reference: [ExpenseSummaryView.vue](src/components/expense/ExpenseSummaryView.vue), [ExpenseBudgetsView.vue](src/components/expense/ExpenseBudgetsView.vue).
- Prefer transform+opacity transitions (compositor-friendly); add `will-change` only on elements that actually animate.

## 16. Showcase transition-stage animation (the reference for "cinematic" motion)

The cover → main-content transition is the app's signature animation. Files: [useShowcaseAnimation.ts](src/composables/showcase/useShowcaseAnimation.ts), [TransitionStage.vue](src/components/showcase/TransitionStage.vue), [TransitionStageDoor.vue](src/components/showcase/TransitionStageDoor.vue), [CoverDecorations.vue](src/components/showcase/cover/CoverDecorations.vue), [DoorPanel.vue](src/components/showcase/cover/DoorPanel.vue).

**Two animation types**, selected by `cover_stage_layout.showcaseAnimationType` (default `decoration`), exposed by `useShowcaseAnimation({ isContentHidden, animationType })` as computed class maps (`coverContainerClasses`, `leftDoorClasses`, `decorationClasses`, `mainContentClasses`). The cover animation is class-driven — a single `isContentHidden` boolean flips CSS classes, no JS tweening — and **each cover animation is paired with its own transition stage**; the two are one look, never mixed.

- **decoration** → [TransitionStage.vue](src/components/showcase/TransitionStage.vue). The four cover decorations slide out directionally (`translateX/Y(±100%)` + fade), 0.8s each, staggered by `transition-delay` 0.1/0.2/0.3/0.4s (left→right→top→bottom) — and [MainContentStage](src/components/showcase/MainContentStage.vue)'s `.animate-slideInFrom*` brings them back on the exact mirror of that: same durations, same stagger, same order, same curve. **Keep the two in sync** — they read as one gesture only because every value matches. The whole chain shares one curve, `--sc-ease-out: cubic-bezier(0.23, 1, 0.32, 1)`, declared on `.showcase-container` and consumed as `var(--sc-ease-out, cubic-bezier(0.23, 1, 0.32, 1))` (the literal fallback covers the manage-page preview frame, which mounts these components outside that container). The stage that follows is the **veil reveal**: photo sharpens out of a blurred bright copy under a Ken Burns drift, bokeh sparkles rise, a frosted footer scrim carries "Save the Date" blooming letter by letter.
- **door** → [TransitionStageDoor.vue](src/components/showcase/TransitionStageDoor.vue). The cover splits into two leaves that swing open in 3D over `DOOR_OPEN_DURATION_MS` (1.65s, [useDoorAnimation.ts](src/composables/showcase/useDoorAnimation.ts) — the single source of truth; the CSS duration and every beat timed off it move together). `transform: translateX(∓62%) rotateY(±82deg)`, `transform-origin: left/right center`. The left leaf starts full-width covering the viewport; the right is a mirrored copy (`width: 200%`, offset content) revealed at open time. Each carries a swing shade on its face and a warm rim light on its inner edge peaking mid-swing. They clear the frame at `DOOR_CLEARED_MS` (1.2s), the swing settling its overshoot off screen after that. The stage that follows is the **curtain-and-cartouche**: an over-exposed photo settling into exposure behind a printed gold frame, with a wiped-in Save-the-Date cartouche, resolving in a gold bloom.
  - **The swing direction is away from the viewer**, not toward: positive `rotateY` on the leaf hinged at its left edge turns its inner edge into the screen, so the cover recedes instead of lunging at the camera.
  - **Perspective belongs to the shared container**, not to each leaf — [CoverContentOverlay.vue](src/components/showcase/CoverContentOverlay.vue)'s `.door-perspective-container` at `1.76 x` the stage width with origin `50% 44%`. A per-element `perspective()` gives each leaf its own vanishing point, and a fixed px value is ~3.3x the width of a phone-shaped stage, which flattens the swing into a horizontal squash.

**Layering matters for door:** `TransitionStageDoor` renders through CoverStage's `#transition` slot at `z-25` — **under** the door panels (`z-28`) and over the main content (`z-20`) — so the doors genuinely part to reveal it. Cross-fading a photo on top of the doors instead reads as a dissolve, not a reveal. `TransitionStage` (decoration) stays a sibling of CoverStage at `z-35`.

**Choreography** (timer-driven with `setTimeout`s, all cleared in `onUnmounted`; emits `transitionComplete`, which the parent's `<Transition>` leave then dissolves):

| Beat | decoration (`TransitionStage`) | door (`TransitionStageDoor`) |
|---|---|---|
| Cover animation | decorations slide out, staggered to ~1.2s | leaves swing 0→1650ms, clear the frame at 1200ms |
| Photo | rises veiled at 400ms as the 5th beat of the cover stagger, lands 1200ms; veil holds then releases 400→2600ms | already there at 0ms, over-exposure settles 250→2600ms |
| Seam light | — | breaks at 0ms, peaks mid-swing, gone by 1550ms |
| Frame / scrim | footer scrim at 1800ms | gold frame draws in at 1250ms |
| Copy | flourish line 1900ms, letter-by-letter bloom from 2200ms, date settles by ~4450ms | centre-out wipes at 1000/1500/2050/2500/2800ms |
| Resolve begins | dissolve at 5800ms, `dissolveStart` mounts main content behind it | gold bloom at 5700ms |
| `transitionComplete` | 7000ms | 6200ms, then an 0.8s leave fade |

The door column's intervals are the reference artwork's own, measured against its curtain rather than restated as absolutes — retiming the swing means retiming all of them together.

**Both flows hand off the same way — the invitation is on screen before the transition stage leaves.** Door does it by construction (main content is mounted throughout the swing, and `door-transition-out` fades the stage over it). Decoration does it via `dissolveStart` → `CoverStage.preRevealMainContent()`, which mounts the main-content slot *without* touching the video state machine — `revealMainContent()`/`skipToMainContent()` would emit `sequentialVideoEnded`, flip the stage to `main_content`, and unmount the transition stage mid-dissolve. The invitation then assembles under the 1.2s dissolve (card 0.8s, ornaments staggered to 1.2s) and lands with it. **Whatever a stage dissolves into must already be mounted**, or the dissolve runs backwards into the screen you just left and the payload hard-cuts in afterwards.

Signature techniques to reuse for similar effects:
- **Reveal by uncovering, not by cross-fading**: when something on top moves away (doors, curtains, wipes), put the payload *behind* it at full opacity rather than fading the payload in on top — no timing or geometry has to be matched, and the motion reads as physical. The same rule governs stage *handoffs*: mount the next stage behind the outgoing one before it starts to go, so its exit is a dissolve into the next thing rather than back to the last one. Two backdrops swapping across that boundary need a transition too — a `v-if` mount plus an untransitioned opacity flip is a cut, and it is only invisible while whatever covers it is still opaque.
- **Over-exposure settle**: to make a photo "arrive from light", stack a screen-blended warm wash (`#fff4dd`, `mix-blend-mode: screen`) plus a radial hot spot and fade both out — far cheaper than animating `filter: brightness()` on a full-bleed image, same read.
- **Seam light**: a fixed-width band at `left: 50%` scaled horizontally (`transform: translateX(-50%) scaleX()`), opacity peaking mid-travel — never an animated `width`, which leaves the compositor.
- **Travelling specular on metal**: a `mix-blend-mode: screen` gradient with `background-size: 260% 100%` animating `background-position`, clipped to a border ring via a `polygon()` `clip-path` built from a single `--inset` custom property, so the highlight only ever rides the frame.
- **Centre-out wipe**: `clip-path: inset(-40% 50% -40% 50%)` → `inset(-40% -3% -40% -3%)`; negative vertical insets keep descenders and drop-shadows outside the clip.
- **Gold lettering**: a gradient with a near-white hotspot, `background-clip: text` + `-webkit-text-fill-color: transparent`, swept by animating `background-position`. **Declare the wipe and the sheen in one `animation` shorthand** — two rules of equal specificity each setting `animation` silently drop the first, which here leaves the text clipped to zero width.
- **The veil is the blender, so keep it near-solid while the payload arrives.** A soft bright copy crossfading over the outgoing screen blends; a *sharp* one dissolving over a sharp screen is a double exposure, and that is what makes a full-bleed reveal look pasted on rather than revealed. The decoration stage learned this from its own mask: opening at alpha `0.25` left the top quarter of the frame 75% sharp during the crossfade — the exact region where the cover still had its title and its top ornament in motion. Open at `0.72` instead: still tilted enough that the faces (high in a portrait crop) clear first, but even enough that what crosses the boundary is soft over sharp everywhere. **Shape the hold into the curve; do not buy it with a delay.** The veil has to stay put while the payload arrives and only then release, and a `transition-delay` gets that — at the cost of two ramps back to back. Both would be ease-outs, so the first decelerates to a full stop before the second begins, and that stop is plainly visible as a two-part reveal. One transition on a strong ease-in-out (`--ts-ease-veil: cubic-bezier(0.77, 0, 0.175, 1)`) across the *whole* reveal does the same job as one motion: ~98% at 800ms and ~85% at 1200ms holds through the arrival exactly as the delay did, then releases. **Two chained ease-outs never read as one gesture — if a beat has to wait, shape it, do not schedule it.**
- **A full-bleed rectangle crossfading in is a slab unless something softens its edges on the way in.** Bring the vignette up *with* the photograph (0.1s behind, matched duration) rather than seconds later. Every other element in a stage like this is soft and graded — veil, mist band, bokeh — so an un-vignetted rectangle is the one hard-edged thing in the frame, and it reads as square. Its opacity multiplies with the container ramp it sits inside, so it arrives gently for free.
- **Veil reveal**: instead of animating `filter: blur()` on a fullscreen image (expensive), stack a pre-blurred bright copy (`blur(16px) brightness(1.18)`) and fade its opacity out over 1.8s — reads as the photo "sharpening". **Draw the veil away rather than dissolving it in place**: a `translateY(-2.5%)` on the same ramp as the opacity turns a blur crossfade into a sheet being lifted off, and pointing it the same way the cover's copy leaves makes the two stages one gesture. That lift is spent out of the copy's oversize, so size the oversize for both — `scale(1.1)` leaves 5% of overhang a side, the lift takes 2.5% of the bottom, and the remaining 2.5% (~21px on an 844px frame) is what still covers a 16px blur. 4% is enough for edge bleed alone and *not* enough once the veil moves.
- **Easing on a multi-second cinematic reveal**: the browser built-ins are too weak to shape one, and `ease-in-out` is outright wrong for an entrance — it holds back at exactly the moment the eye arrives. Declare two curves on the stage root and use nothing else: `--ts-ease-out: cubic-bezier(0.23, 1, 0.32, 1)` for drawn chrome and copy, `--ts-ease-atmos: cubic-bezier(0.33, 1, 0.68, 1)` (easeOutCubic) for full-frame image layers, where the strong curve arrives too abruptly to read as atmosphere, and `--ts-ease-veil: cubic-bezier(0.77, 0, 0.175, 1)` for anything that must hold its position before releasing (see the veil rule below). Where two layers are meant to hand off to each other — the transition stage's photo fade and the petal field that replaces the cover's — they must share the *same* duration **and** curve, or the handoff shows.
- **Make the arriving thing a beat of the outgoing stagger, not an event after it.** The cover's four ornaments start at 100/200/300/400ms and each takes 0.8s; the transition photograph starts at 400ms and takes the same 0.8s, so it is the fifth beat and lands with the last ornament at 1200ms. Same clock, same duration — only the curve differs, and deliberately: the ornaments leave on the chain's strong curve because they are objects being pulled off, the photograph arrives on the gentler `--ts-ease-atmos` because it is light filling the frame. Matching the duration is what removes the drift that reads as "unsynced"; matching the curve as well would make the photograph slam.
- **Time a stage's arrival against the previous stage's exit clock, not against its own mount.** The decoration transition mounts on the envelope tap, so both clocks are the same one — and the cover's ornaments (100→1200ms, on a strong curve that has them visually gone by ~900ms) are what the photograph has to interlock with. Starting the photograph after that exit finished read as three events: ornaments leave, a beat of bare backdrop, a photo bleeds in. Starting it at 400ms puts its rise underneath the exit's tail, so the ornaments travel out *through* a photograph already coming up and the frame changes hands once. Check the arrival against `coverExitDurationMs()` too — that is the view's own answer to "when has the guest stopped looking at the cover?" and it cues the music there.
- **The showcase has one arc: the frame opens outward, then closes inward — put the payload's *scale* on that arc.** Synchronising a stage's arrival to the previous stage's exit removes the drift; giving it the same *direction* is what makes the two read as one motion. The cover's four ornaments leave outward (±100% on each axis), which at frame level is one outward gesture, so the transition photograph expands into the space they vacate (`scale(0.94)` → `1`). The invitation's ornaments then fly *inward* from the edges, so the photograph contracts as it dissolves (`1` → `0.985`) and everything converges on the centre together. A payload that only fades at a boundary leaves the incoming frame closing over a still image. Contracting `1.03` → `1` on the way in is a fine "camera settling" in isolation and exactly backwards here — the frame opened while the photograph closed.
- **Budget the edge coverage before choosing the exit motion.** Any scale below 1, or any translate, on a layer stacked over the Ken Burns frame eats the overhang that keeps the photo's edge outside the frame — and the composite, not either value alone, is what must stay above 1. Ken Burns is only ~1.03 six seconds in and has translated the photo up 0.6% by then, most of which is spent out of the *bottom* overhang. **A contraction costs half its value per side; a translate spends its whole value on one edge**, so scale buys twice the motion for the same budget. Write the arithmetic into the comment — the tight frame is at the end of the dissolve, where opacity is already 0.
- **Gate a timed reveal on the asset actually being decoded.** A reveal choreographed against another stage's exit only works if the thing revealed is there to reveal; an image still in flight pops in over the middle of its own fade and the interlock is lost. Wait for `load`, with a ceiling (`PHOTO_REVEAL_LATEST_MS`) so a slow or broken asset delays the handover rather than stalling the stage.
- **Ken Burns**: run the drift (`scale 1.14→1.02` + slight translateY, 9s `cubic-bezier(0.25,0.1,0.25,1)`) on a wrapper frame so it composes with the container's opacity fade.
- **Camera and subject move against each other**: the door stage nests a dolly (`scale 1→1.18→1.3`, origin `50% 44%`) around a Ken Burns that eases *back* and drifts the other way (`scale 1.12→0.98`, `translateX 2.2%→-2.2%`). Opposed motions read as depth; matching them just reads as one bigger zoom. Two things follow — the dolly's early leg has to be a hard push (1→1.18 inside the first 1.7s, with a per-keyframe `animation-timing-function` so each leg eases on its own; one ease across the whole span flattens the arrival), and since the inner scale dips below 1, check the *composite* never drops under 1 or the photo's edge appears inside the frame.
- **One-shot light sweep**: diagonal white gradient band translated `-100%→100%`, `linear` with a delay so it fires after the veil lifts. **Peak the brightness where the band is actually on screen** — 0 → 1 by 22%, 1 → 0 after 78% — and `linear`, not `ease-in-out`: a band that starts at full opacity spends it off the left edge and is already half-faded crossing the subject, and an eased sweep crawls at the off-screen ends and hurries through the visible part. Both read as a smear instead of a pass of light. Time it to *clear* before the stage dissolves, not merely to start before it.
- **Letter-by-letter bloom**: split text into `<span>`s, each starting `opacity-0 blur(6px) translateY(8px)`, animating in with `cubic-bezier(0.22, 1, 0.36, 1)` and inline `animation-delay: base + i * 65ms`. The `base` matters when a rule or flourish sits above the copy: **the frame is set before the copy fills it**, so hold the letters ~400ms and let the line land first. Note the delay has to be folded into the *inline* value — a base delay in the stylesheet is overridden by the per-character inline one.
- **Letter-spacing track-in**: date fades in while `letter-spacing` settles 0.36em → 0.18em. Two things travel with it. (1) `letter-spacing` also adds a trailing space after the *last* glyph, so a centred line sits half a space left of true centre — by a changing amount as the tracking closes, which makes the copy visibly creep sideways. Cancel it with a `margin-right` animated in lockstep (`-0.36em → -0.18em`). (2) It is a layout property, so the line can *wrap* at its widest tracking and unwrap partway through, jerking everything above it. Give it `white-space: nowrap` and size it against the stage (`clamp(0.62rem, calc(var(--ts-w) * 0.029), 0.85rem)`) — the longest en-US long date runs ~400px at 0.85rem/0.42em, wider than a 390px phone.
- **Bokeh particles**: randomized once per mount (position/size/drift/duration as CSS custom properties), float upward via `@keyframes` on `--drift-x`/`--float-duration`. **An infinitely looping particle must reach opacity 0 at both ends of its loop** — put the peak in a custom property (`--bokeh-peak`) and the envelope in the keyframes, never a fixed `opacity` on the element: a mote still lit at the top of its travel teleports back to the bottom at that same brightness every cycle. It also stops motes sitting visible and motionless through their `animation-delay`. Use `linear` for the rise and let an intermediate keyframe bend the horizontal drift, so the path curves without the vertical speed pulsing.
- **Template-driven color**: every color comes from template props (`primaryColor`, `accentColor`, `blurEffectColor`) with hex+alpha string concatenation (e.g. `${c}4d`) for gradients — never hardcode showcase colors. Where a "metal" needs a specular highlight, keep the base hue template-driven and the hotspot a fixed near-white: any polished surface's highlight is near-white whatever its base hue.
- **A stage's display face can be fixed rather than template-driven** when it's part of reproduced artwork — the decoration stage pins its label to `'Great Vibes'`, the door stage's whole cartouche to `'Cormorant Garamond', 'Kantumruy Pro', Georgia, serif`. Both are already loaded app-wide in [index.html](index.html), so pinning one costs no extra request. It matters because size/tracking/weight are tuned *per face*: a high-contrast display serif's 600 is a workaday serif's 400, so handing the same numbers to an arbitrary template font comes out blunt. Template font slots still drive everything that renders the organizer's own content.
- **`blurEffectColor` is the colour of anything washed over imagery** — mist bands, scrims, plates, printed mats. `primaryColor`/`backgroundColor` are the *cover's* colours and read wrong laid over a photo. It comes from the template's `blur-effect` slot and **defaults to `#ffffff`**, so assume light: normalize the hex, derive relative luminance (`0.2126r + 0.7152g + 0.0722b > 0.6`), and swap anything tuned for a dark plate — the deep-black `drop-shadow` stack that gives lettering weight becomes a grey smudge on ivory, and a scrim stop heavy enough to read as depth becomes a haze over the subject's face.
- **Size against the stage's width, not the viewport's**: `.showcase-container` is `min(100vw, 56.25vh)` — height-constrained on desktop, width-constrained on a phone. Plain `vw` blows chrome up on a wide desktop where the stage is no wider than a phone; plain `vh` (the `clamp(min, Xvh, max)` pattern in [cover-stage-styles.css](src/components/showcase/cover-stage-styles.css)) is right only where height is the constraint — on a 390×844 phone it runs ~20% large against the width, which reads as heavy, crowded chrome. For anything whose proportion to the *frame* matters, declare `--w: min(100vw, 56.25vh)` on the stage root and size everything as `calc(var(--w) * ratio)`; when porting from reference artwork, the ratio is just `originalPx / originalWidth` — see [TransitionStageDoor.vue](src/components/showcase/TransitionStageDoor.vue), where each value carries its source pixel in a comment.
- Overlay stages use `position: absolute; inset: 0; pointer-events: none` with explicit z-index layering inside the stage.

**Always include `@media (prefers-reduced-motion: reduce)`** for showcase-grade animations: kill Ken Burns/sweeps/particles, shorten fades, zero out stagger delays.

## 17. Responsive & cross-device rules

- **Mobile-first always**: base classes target phones; scale up with `sm:` (640) → `md:` (768) → `lg:` (1024, the nav switch) → `xl:`/`2xl:`. Custom wide breakpoints exist (`3xl` 1920, `4xl` 2560) — use only for showcase/full-bleed layouts.
- Standard responsive bumps: text `text-xs sm:text-sm` / `text-sm sm:text-base`, padding `p-4 sm:p-5 md:p-6`, gaps `gap-2 sm:gap-3`.
- Touch targets ≥ 40px on mobile (`min-h-[40px]`, `w-10 h-10`); they may shrink on desktop (`md:w-8 md:h-8`). Hover-only affordances must have a mobile path (always-visible on touch, or an explicit menu).
- Horizontal overflow is handled per-container (`overflow-x-auto scrollbar-hide` + gradient edge fades), never by letting the page scroll sideways.
- Scrollable panels inside overlays use `overscroll-contain`; decorative scrollbars use the thin 6px style (§10).
- Grids collapse to one column on mobile: `grid-cols-1 sm:grid-cols-2` (forms), `grid-cols-1 md:grid-cols-2 lg:grid-cols-3` (card grids).
- No dark mode, no RTL; but every string must work in both English and Khmer (Khmer runs longer — avoid fixed widths on text containers).

## 18. Component conventions & accessibility

- Vue 3 `<script setup lang="ts">`, typed `Props`/`Emits` interfaces with `defineProps`/`defineEmits`; reusable states (empty/skeleton/filter) become small prop-driven components under the feature folder.
- Icons: `lucide-vue-next` only; sizes `w-4 h-4` (inline/meta/buttons), `w-5 h-5` (nav/toasts), `w-6 h-6` (FAB), larger only in icon discs.
- Accessibility: `role`/`aria-label` on interactive cards, `role="switch"` + `aria-checked` on toggles, `aria-hidden="true"` on decorative layers, `title` or `aria-label` on every icon-only button, `alt` on meaningful images (empty `alt` + `aria-hidden` on duplicates/decorative). Keyboard: everything clickable is a real `<button>`/`<a>`; Escape closes overlays; visible focus via the sky ring pattern.
- Sanitize any user-generated HTML with the DOMPurify utils before `v-html`.

## 19. New-UI checklist

Before finishing any new page/component, verify:
1. Four states exist (loading skeleton, content, empty, error) and match §13.
2. All strings i18n'd in `en` **and** `kh`.
3. Neutral colors are `slate-*` only; CTAs use the brand hex gradient.
4. Radius/shadow chosen from §3's scale; overlays use the §14 z-index ladder.
5. Works at 375px, 768px, 1024px, and 1536px — no horizontal page scroll, touch targets ≥ 40px, fixed bottom elements clear the mobile tab bar.
6. Transitions come from §15's named set; any large animation respects `prefers-reduced-motion`.
7. Icon-only buttons have labels; toggles/switches have ARIA roles; focus is visible.
